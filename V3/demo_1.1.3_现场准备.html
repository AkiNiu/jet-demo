现场准备 — 到场确认

工作负责人到达现场后，确认到场定位、拍照留证、确认人员到位情况。本页面对应 2.2 产品设计底稿。

设计决策

  • 页面核心是"到场打卡"，不是"填表"——定位确认做成顶部Hero Card；定位文本同时作为全项目所有后续照片/视频的水印基准
  • 水印文本结构（D23）——"现场准备定位拼接 + 时间戳 + 数据项名称"三段；数据项名称沿用 2.4 机制从项目快照动态取，不硬编码、不新建配置模块
  • 三层视觉重量 + 排列原则——Hero定位（最重）→ 拍照/枚举（中等）→ toggle确认项（最轻）。组内"独特交互前置，相同toggle后置"
  • 与作业前准备形成"发出→验收"闭环——工程车辆/配合事项在闭环项下方灰色小字提示前后关系
  • 从2.4 的33+次操作精简到4-5步——定位+拍照+选电压+一键合格+提交
  • 水印修改申请（V3.1 D20）——活干完发现水印错 → 工作负责人发起申请 → 项目经理审批 → 批量改水印+重渲染 → 部门经理知情通知 → 操作日志留痕
  • V3.0 定位仅存档（D21）——GPS坐标先存不用；V3.1 作为锚点坐标支撑模拟定位检测+漂移校验
  • 水印附定位方式标记（D22）——GPS/网络/手动输入，管理者可据此识别异常定位占比
  • 站房安措模式已从此页面移除——移至 3.3 安措执行模块的"逐站房独立解锁"机制

管理者视角要点（本模块是廉政管控核心场景）

  • 廉政（P1-P8）——代打卡 / GPS模拟 / 水印造假 / 挂名 / 车辆照片盗用 / 不合格勾合格 / 水印修改申请滥用 / 电压等级错选。V3.0 数据预留定位坐标+定位方式+操作人+设备+IP+EXIF；V3.1 做模拟定位检测+锚点校验+异地登录预警+EXIF校验+水印修改申请
  • 安全（S1-S4）——定位失败强行打卡 / 电压错选影响阈值 / 电源搭接判定失真 / 车辆未到应急隐患
  • 规范——不合格三维 / 闭环关系 / 工单快照机制 / 水印数据项名称来自项目快照 与 2.1/2.5 跨模块一致
  • 效率——主路径4-5步（vs 2.4 的33+次操作）

系统管控边界

系统负责"让违规可见、可追溯、可管理"，不负责"让违规不可能"。显式不管的：① V3.0 不验证 GPS 真伪（仅附定位方式标记）；② V3.0 不阻止水印编辑造假（V3.1 修改申请兜底）；③ V3.0 不强校验车辆照片真伪（仅靠水印间接证）；④ 主业/配合人员实际到场的真实性（靠开工会照片+组织制度）；⑤ 纸质工作票实物（归纸质）；⑥ 账号是否本人使用（靠单设备登录+组织制度）。

字段与交互预期

  • Hero 定位：GPS（高德SDK融合定位，自动选GPS/WiFi/基站源）→ 失败兜底手动输入 → 附"手动定位"标记 → 自动拼接项目名称（可编辑）→ 附"定位方式"水印标签（GPS/网络/手动）
  • 工程车辆照片：1-5 张，现场实拍不可相册选取，照片带水印（水印文本 = 本模块定位文本 + 时间戳 + 数据项名称"工程车辆"）
  • 电压等级：10kV / 20kV 枚举单选，无默认值
  • 9项 toggle + 不合格原因（多选≥1）+ 补充备注（选填）
  • 提交留痕：提交时间、操作人、设备、IP、定位坐标（V3.1 锚点用）、定位方式标记、判定方式不记录（D18）
  • 检查项/不合格原因来自数据配置模块租户级配置，工单创建时复制为快照

水印数据项名称来源（D23 沿用 2.4 机制）

拍照时按"数据类型 + itemId"查项目快照表的 name 字段动态取，不硬编码。水印 3 行：① 数据项名称（动态取）② 时间戳 ③ 现场准备定位文本（全项目沿用）。V3.0 不新建水印配置模块。详见 参考资料/2.4水印实现调研_20260414.md

状态机归属

本模块不定义状态机。工单级状态由主PRD第五章+1.0维护；BIGA流程图卡片视觉由 1.0 项目工作台渲染；本模块仅以"有无提交记录"二元事实判断角色可见性和点击行为。

异常兜底（4类覆盖）

网络（断网/响应丢失/照片上传失败/加载失败）、数据（摘要/检查项/原因选项加载失败）、冲突（重复点击/多设备登录/上游未完成/重新定位未确认）、权限（非工作负责人/登录过期/相机权限/定位权限）、业务（GPS失败/水印空/车辆未拍/电压未选/不合格原因/中断退出）。详见底稿 4.7。
