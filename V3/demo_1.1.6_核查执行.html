工作负责人将6~8项核查任务按人分配给4名试验人员。完整分工交互见独立Demo。

设计决策

  • 按人分配，没有"组"的概念——4张人员卡片+任务chip标签，"先想人再分活"
  • 每项任务只有1个试验负责人——负责判定，其他人可协助拍照
  • 必须全部分配才能提交——提交前强制校验，未分配项高亮提示
  • 本页为简化展示——仅展示分工结果预览，完整交互（添加/移动/取消/提交确认弹窗）见 demo_核查分工.html

P2 · 核查执行 + 判定

试验人员并行执行 6~8 项核查任务——拍照留证+整项判定。

设计决策说明

  • 按拍照模式分两种页面——8 项核查按配置走不同交互，但共享判定区+不合格流程：
    · 必填拍照 5 项（电源/建设/居民入住/充电/居民设施）→ 自定义取景窗：连续多槽位拍照+快门+拍完后展开判定
    · 选填判定 3 项（送电痕迹/临电电源/安全风险）→ judge-toggle 判定页：复用作业前准备的合格/不合格组件，下方"添加照片（选填）"调原生相机
  • 拍照只留证，判定只有一层——拍照回答"现场长什么样"，判定回答"合不合格"。每项由判定人做一次整项判定
  • 不合格流程统一——两种页面共用：原因勾选（至少1项）+ 留证照片（至少1张）
  • 全部核查项并行，无前置关卡——2.4 系统的"电源核查强制关卡"已取消，4 人各做各的，干完帮别人
  • 照片可多不可少——客户端 5 张/槽软上限，服务端不拦截
  • 离线优先+后台静默上传——拍照存本地→有网时后台自动逐张上传（用户无感）→判定前强制联网同步+确认面板（"基于以下N张照片做判定"）。不做 WebSocket/轮询
  • 每人只操作自己被分配的项——V3.0 Demo 展示核心流程。帮拍（维度2：瞬间配合留痕）待老板拍板后决定是否加入，详见产品设计底稿版本边界
  • 三种改派通道（维度1：任务分配）——①退回时改派②B自主申请③工作负责人主动改派。详见 2.4 底稿 3.6-3.7

P3 · 核查确认

工作负责人审核全部核查结果，逐项确认通过或退回重做。这是涉电作业前的安全二重屏障：试验人员漏看/敷衍的问题，工作负责人在确认环节再拦一次。

设计决策说明

  • 工作负责人独有页面——试验人员不操作 P3，只在 P2 提交判定后等待确认
  • 硬前置 3.7 检测数据采集（重大修正 2026-04-14）——8 项核查全部"已确认"才允许开始涉电检测。不阻塞抽检对象/安措/开工会/检测分工等非涉电环节（工作负责人可在车上/碎片时间审核）
  • 确认即锁定，退回保留草稿——确认通过后永久锁定；退回后原照片+原判定保留为草稿（不清空），试验负责人基于草稿局部修改即可重提，不强制全部重做
  • 退回原因必填 ≥10 字（修订 2026-04-14）——从原"选填"改为"必填 ≥10 字"，引导工作负责人写清楚具体错漏点，避免草率退回
  • 三种改派通道（维度1：任务分配）——①退回时改派（工作负责人发起，已判定的项）②B自主申请改派（任务持有人发起，做不完时）③工作负责人主动改派（肉眼发现异常时）。并发冲突：③>②>①。详见 2.4 底稿 3.6-3.7
  • 确认通过需二次确认弹窗——防误操作，确认后不可撤回

请试试以下操作

  • 1. 先去 P2 完成几项核查并提交判定
  • 2. 回到 P3，看到"待确认"的项
  • 3. 点击待确认项 → 查看照片+判定详情
  • 4. 点"确认通过"→ 二次确认弹窗 → 该项锁定
  • 5. 或点"退回"→ 填写原因（≥10 字必填）+ 可选勾选"同时改派给 XX"→ 该项保留草稿状态
  • 6. 回到 P2 查看退回效果（状态变红，点击显示退回原因，原数据作草稿可修改）

  • 核查确认作为旁支任务（流程引擎支持），主链路推进不等

退回操作的数据处理

  • 退回后 原数据保留为草稿（不清空 photos/judgment/reasons），标记 returned=true 并保留 retReason
  • 试验负责人进入该项 → 顶部高亮展示 retReason → 基于草稿修改（可单独替换某张照片）→ 重提后 returned=false 状态回到待判定

确认操作

设置 confirmed=true + 记录 confirm_by+confirm_time，该项在 P2 永久锁定，不可再次修改。

分配变更历史追加（配合 2.4）

退回时勾选改派 → 在分配变更历史表追加一条"改派+操作人+原负责人+新负责人+改派原因+时间"；试验负责人字段更新为新负责人。
