建设情况确认

工作负责人到场后，核实站房数量/编号/类型，确认配套设施和进线电缆段数——为下游全部环节建立站房数据基础。

设计决策

  • 从2.4系统38+次点击减少80%+——2.4系统要求16字段×N站房全量录入。3.0只保留核查必须的2个字段（编号+类型），其余延后到抽检对象确认时补填
  • 核实+修正，不是从零录入——工单创建时系统已按项目规模自动生成站房记录和默认编号，工作负责人到场后只需对照现场核实，编号对就直接确认，不对才改
  • 确认和改编号是同一个动作——点击站房行→看到当前编号→没问题直接点确定（确认），要改就改完点确定（修改）。不存在单独的确认按钮
  • 配套设施用"有/无"双按钮，不用勾选框——勾选框的"未勾选"无法区分"用户选了无"还是"用户没看到"。双按钮保证用户一定看过并做了选择
  • 提交时规模校验不阻断——当前数量与工单规模不一致时弹出提醒，但允许继续提交（现场实际规模确实可能与工单不同）
  • 提交后不可修改，兜底在包裹阶段——站房编号是全流程数据源，中间环节修改影响面过大。在包裹导出前提供"站房编号校正"功能统一调整

业务规则

规则说明
站房列表来源工单创建时按项目规模自动生成，预设默认编号（1、2、3...）
站房CRUD可新增（选类型→输编号）、可删除（左滑→二次确认，至少保留1个）、可改编号（点击行→输入框）
编号唯一同类型内编号不可重复，重复则Toast提示
配套设施充电桩和居民设施各选"有/无"，选"有"→下游核查分工出现对应任务
进线段数Radio（1/2/3段），全局设置，影响电源核查拍照数量
提交条件全部站房编号已确认 + 配套设施已选 + 进线段数已选
规模校验与工单规模逐类型对比，不一致弹提醒（不阻断）
中断不保留退出重进需重新操作
引导文案顶部提示"请确认全部站房，包括不抽检的"

与上下游的关系

方向数据用途
上游（工单创建）站房列表+默认编号预生成，到场核实
下游（核查分工）配套设施勾选控制充电/居民核查任务是否出现
下游（电源核查）进线段数确定每站房有几路进线。试验负责人在电源核查执行时再逐路确认电缆状态（未敷设/未搭接/已搭接），系统据此条件显隐对应拍照项
下游（抽检对象确认）全部站房列表标记抽中+补填详细属性
兜底（包裹阶段）站房编号导出前可校正编号

后处理链

  • verifyComplete() → 校验所有站房已确认 + 规模弱匹配
  • confirmStationRoomInfo() → syncCheckInfo()生成核查项快照（8大核查项Set→Group→Item三层）
  • 充电/居民核查项由 chargingSetCompleteFlag / residentialFacilityCompleteFlag 控制生成
  • 电源核查子项按进线段数裁剪

提交数据

站房列表（编号+类型）+ 充电桩设施flag + 居民设施flag + 进线段数 + 时间 + 操作人

关键数据存储

站房数据: PrjStationRoomInfo表（23字段，本环节填2个，其余在抽检对象确认时补填）

电源核查V3.0条件显隐（下游影响，由试验负责人在核查执行时操作）

建设情况确认提供进线段数（确定每站房几路进线），试验负责人在电源核查执行时逐路确认电缆状态，系统据此条件显隐拍照项：

上级电源侧状态本地侧状态显示的拍照项
未敷设—跳过，不生成拍照任务
未搭接（悬空）本地也未搭接电缆端子悬空照 + 临时接地线照 + 进线柜分闸照
未搭接（悬空）本地已搭接进线柜分闸照 + 隔离刀闸断开照 + 接地刀闸合闸照
已搭接检修（已挂接地）进线柜分闸照 + 接地刀闸合闸照
已搭接冷备用（无接地）进线柜分闸照 + 高压验电确认照
