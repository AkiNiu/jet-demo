作业前准备

合规过门页——工作负责人确认材料、人员、项目准备就绪。本页面对应 2.1 产品设计底稿。

设计决策

  • 从2.4的21+次操作精简到2次点击——"一键全部合格"让90%+场景2步<5秒完成
  • 合规过门页，留痕为主——独立存在价值：新人出发检查清单 + 售前展示规范覆盖 + 合规留痕支撑管理者看板（V3.1不合格数据统计）
  • 不能默认全合格——必须由工作负责人主动点击确认（D1，花工原话"和供电公司领导交代不了"）
  • 不合格记录三维结构——结果（合格/不合格）+ 原因（可配置选项，多选≥1）+ 补充备注（选填）。V3.0 不回退不中止流程
  • 配合事项一键复制——结构化文本→剪贴板→微信发给供电公司专职。V3.0 支持临时编辑后复制（仅本次不保存个人模板，D16）
  • 入口与可见性（无状态机）——BIGA工作台卡片始终可见；点击按"有无提交记录+角色"分层：未提交时其他角色进入提示"工作负责人尚未提交"，已提交后所有角色可只读查看

管理者视角要点

  • 廉政（P1-P5）——一键过但物资不齐 / 配合事项未真发 / 不合格勾合格 / 挂名 / 账号共享。V3.0 数据预留提交时长+操作人+设备+IP；V3.1 看板做"一键率+提交时长<5秒+全合格"的"走过场"预警
  • 安全（S1-S3）——材料实际未备 / 主业联系失败 / 人员资质过期。V3.1 与 1.0 工单派发资质校验协同
  • 规范——一键合格 UI 范式 / 不合格三维语义 / 工单快照机制 与 2.2 跨模块一致
  • 效率——2步<5秒的主路径（vs 2.4 系统 21+ 次操作）

系统管控边界

系统负责"让违规可见、可追溯、可管理"，不负责"让违规不可能"。显式不管的：① 一键合格的真实性（不强制查看每项）；② 配合事项是否真的发了（仅提供复制能力）；③ 账号是否本人使用（靠单设备登录+组织制度）；④ 工作服/安全帽等实物穿戴检查（归纸质）。

字段与交互预期

  • 7项检查的每项结果 + 不合格原因数组（多选）+ 补充备注文本
  • 提交留痕字段：提交时间、操作人、设备、IP（V3.1 审计用）、进入页面时间（V3.1 看板算操作时长）；判定方式不记录（D13）
  • 检查项/不合格原因来自数据配置模块的租户级配置；工单创建时复制为快照，已派发工单不受后续配置改动影响
  • 配合事项模板：公司级固定（V3.0），APP 支持临时编辑后复制到剪贴板

状态机归属

本模块不定义状态机。工单级状态由主PRD第五章+1.0维护；BIGA流程图卡片视觉由 1.0 项目工作台渲染；本模块仅以"有无提交记录"二元事实判断角色可见性和点击行为。

异常兜底

覆盖四类：网络（断网/响应丢失）、数据（配置加载失败）、冲突（重复点击/多设备登录/工单被撤销）、权限（非工作负责人误进/登录过期）。详见底稿 4.6。
